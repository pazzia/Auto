# АвтоХаб — слой API и заглушки

Все экраны получают данные только через `window.AutoHubApi` (`web/api.js`). Бэкенд, когда появится,
должен реализовать эти же методы по путям из колонки «Путь (live)» — тогда фронтенд менять не придётся.

## Режимы

| Режим | Как включить | Что происходит |
| --- | --- | --- |
| `mock` | по умолчанию | Заглушки: демо-данные, имитация задержки сети 250–700 мс, интернет не нужен |
| `live` | `?api=live` в адресе или `window.AUTOHUB_CONFIG = { mode: "live", baseUrl: "https://…" }` до подключения `api.js` | VIN и модели — NHTSA vPIC; остальное — бэкенд `baseUrl`. Пока `baseUrl` пуст, методы возвращают ошибку `not_configured` |

В Android-приложении запросы live-режима к vPIC идут через нативный мост `NativeHttp.kt` (белый список хостов).
Адрес бэкенда нужно будет добавить в этот список.

## Методы

Асинхронные методы возвращают `Promise`. Ошибка — `Error` с полем `code`:

| `code` | Когда |
| --- | --- |
| `not_configured` | режим `live`, а `baseUrl` бэкенда не задан |
| `network` | запрос не дошёл: нет интернета, DNS, CORS, обрыв соединения |
| `timeout` | запрос к vPIC не ответил за 12 секунд |
| `bad_json` | сервер ответил 200, но тело не JSON (например, HTML-страница прокси или капча) |
| `http_<код>` | сервер ответил ошибкой, например `http_503` |
| `not_found` | объект не найден (номер в демо-базе, деталь) |
| `bad_request` | не хватает параметров (`services.book` без `serviceId` или `slot`) |

Текст для пользователя по коду даёт `AutoHubApi.errorText(e)` — экраны показывают его вместо бесконечного «Загружаем…».
В каждом ответе заглушки есть `source: "Демо-данные (заглушка API)"`.

| Метод | Путь (live) | Кто даст данные в рабочей версии | Где используется в прототипе |
| --- | --- | --- | --- |
| `userPosition()` | `GET /v1/me/position` | Геолокация устройства | «Автосервисы», если нет адреса из кабинета |
| `vehicle.decodeVin(vin)` | NHTSA vPIC | vPIC + Laximo/Acat | «Добавить авто» → VIN |
| `vehicle.findByPlate(plate, region)` | `GET /v1/vehicles/by-plate` | AvtoVinCod, Автокод, apipoint (платно) | «Добавить авто» → Госномер |
| `vehicle.modelsForMake(make)` | NHTSA vPIC | Справочник поставщика | «Добавить авто» → Марка |
| `maintenance.options(slot)` | `GET /v1/maintenance/parts?slot=` | Exist, Emex, Автопитер, ZZap, Autodoc (API площадок) | Сценарий ТО → запчасти, бюджет, «Запчасти» |
| `parts.search({query, cat, kit})` | `GET /v1/parts/search?query=&cat=&kit=` | API магазинов + подбор по VIN | «Запчасти» → результаты |
| `parts.get(partId)` | `GET /v1/parts/{id}` | API магазинов | «Сравнение» |
| `parts.offers(partId)` | `GET /v1/parts/{id}/offers` | API магазинов | «Цены продавцов» |
| `services.list({lat, lng, online, to, today, tires})` | `GET /v1/services` | Каталог сервисов + CRM | «Автосервисы», сценарий ТО → сервис |
| `services.slots(serviceId, date)` | `GET /v1/services/{id}/slots` | YCLIENTS, STOCRM, АвтоДилер | готово к подключению |
| `services.book({serviceId, slot, works})` | `POST /v1/bookings` | CRM сервиса | готово к подключению |
| `fines.list(car)` | `GET /v1/fines?plate=&region=` | Платёжный партнёр (ГИС ГМП) | «Штрафы», баннер в гараже, плитка «Штрафы» |
| `fines.pay(ids)` | `POST /v1/fines/pay` | Платёжный партнёр | «Штрафы» → оплата; ответ `{ receipts: [{ fineId, receipt, paidAt }] }` |
| `insurance.quotes(car, kind)` | `GET /v1/insurance/quotes` | Брокер или агрегатор | «Страховка» → цены ОСАГО |
| `tires.advice(pos)` | `GET /v1/tires/advice` | API погоды | готово к подключению |
| `ai.ask({message, node, car})` | `POST /v1/ai/ask` | Сервер-прокси с LLM (AUTO-4) | AI-механик (AUTO-3) |
| `sos.request(req)` | `POST /v1/sos` | Оператор помощи на дорогах | «Помощь на дороге» → эвакуатор, техпомощь |

«Готово к подключению» — метод и демо-данные есть, но экран пока свёрстан статично из макета.

Штраф: `{ id, date, time, article, text, place, uin, amount, discountUntil, discountAmount }`. Скидка 50% действует
по `discountUntil` включительно, потом к оплате `amount`. В заглушке штрафы есть только у демо-машины гаража
(`car.demo`), даты — от сегодняшнего дня; у машин, добавленных пользователем, список пустой.

### Синхронные методы (расчёт на телефоне, без сети, одинаково в `mock` и `live`)

| Метод | Что возвращает | Где используется |
| --- | --- | --- |
| `maintenance.nextTO(car)` | `{ km, left, overdue, soon, noMileage, items, parts }` — ближайшее ТО по пробегу и `lastTOkm` | Гараж, «Запчасти», сценарий ТО, механик, бюджет |
| `maintenance.worksPrice(service, items)` | цена работ: `service.priceTO` + доплаты работ регламента | «Автосервисы», «Запись в сервис», сценарий ТО — одна цифра везде |
| `maintenance.priceVerdict(price, market)` | `{ verdict: ok \| high \| low, diffPct }` | «Автосервисы», «Запись в сервис» |
| `maintenance.step` | шаг регламента, км (15 000) | сценарий ТО |
| `parts.find(partId)`, `parts.priceTable(partId)` | деталь и цены продавцов из локального демо-каталога | корзина |
| `parts.categories`, `parts.sellers` | справочники | «Запчасти», корзина |
| `vehicle.demoPlates()` | госномера демо-базы | подсказка в «Добавить авто» |
| `errorText(e)` | текст ошибки по `code` | все экраны с загрузкой |

`parts.find` и `parts.priceTable` работают только с локальным каталогом: при подключении бэкенда корзине
понадобятся асинхронные аналоги (цены продавцов придут из `parts.offers`).

Правила `nextTO`: без отметки о прошлом ТО следующее — ближайшее кратное 15 000 км, ровно 45 000 км — это ТО-45 000.
С `lastTOkm` — `lastTOkm + 15 000`; если пропущено больше одного ТО, ближайшее — последнее кратное шагу, которое уже пройдено,
и статус остаётся «пора» (`overdue`, `left ≤ 0`). Состав работ — по номеру ТО в регламенте.

Марки из vPIC приходят заглавными: известные пишутся по таблице (`BMW`, `Mercedes-Benz`, `Kia`, `Škoda`, `ГАЗ`),
остальные — с заглавной буквы в каждом слове, дефисы сохраняются; слово до трёх букв без гласных считается аббревиатурой (`GMC`).

Автосервисы: 13 демо-точек в Подмосковье вокруг Красногорска (позиция пользователя в демо).
Названия — плейсхолдеры `[Название]`, цены и рейтинги демонстрационные. Медиана цены ТО для «честного ценника» — 4 600 ₽.

## Карта

Статическая схема Московской области: `web/map/podmoskovye.svg`, генерируется `tools/make_map.py`
из упрощённых координат (граница, МКАД, ЦКАД схематично, 11 вылетных магистралей, Ока и Москва-река, 44 города).
Это схема для прототипа, не для навигации. Проекция: 1 единица viewBox = 1 км,
`x = (lon − 35) · 62,65`, `y = (57 − lat) · 111,2`; параметры записаны в `data-*` атрибутах SVG.

В рабочей версии карту заменит коммерческая лицензия 2ГИС или Яндекса (см. риски в дорожной карте).
