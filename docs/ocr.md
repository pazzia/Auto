# OCR на Android без сервера — AUTO-39

Ветка `feature/document-ocr`, сборка **0.10**, отдельное приложение «АвтоХаб OCR» (`ru.autohub.app.ocr`). Основное приложение не заменяется. Версия 0.10 обновляется поверх OCR 0.9 с сохранением его локальных данных.

## Пользовательский сценарий

1. Добавить свою машину в гараж.
2. История → «+ Запись» → «Сканировать наряд-заказ».
3. Снять документ камерой или выбрать JPG/PNG/WEBP/PDF. До 10 страниц и 16 МБ суммарно, один наряд-заказ за раз.
4. При необходимости задать поворот страниц. Нажать «Распознать на устройстве».
5. Дождаться завершения; видна текущая страница, есть отмена. Во время обработки держать приложение открытым.
6. Проверить поля, текст и изображения страниц. Исправить ошибки, подтвердить выполненные работы, сохранить.

**Сервера, ключей, регистрации у OCR-провайдера, LLM, оплаты за страницы и интернета для OCR нет.** Русская и английская модели встроены в APK. Даже первый запуск распознавания возможен в авиарежиме. Остальные существующие функции приложения (например, внешние автомобильные API и сетевые шрифты) могут обращаться к сети; это не часть OCR.

## Архитектура

- Tesseract4Android 4.9.0, стандартная CPU-версия, Tesseract LSTM `rus+eng`.
- `OfflineOcrEngine.kt`: копирует проверенные модели из APK во внутренний каталог приложения; обрабатывает фото с EXIF, поворот, PDF через Android PdfRenderer; освобождает bitmap после каждой страницы.
- `OcrPreprocess.java` (сборка 0.15, AUTO-41): перед OCR снимок переводится в оттенки серого, масштабируется Lanczos-3 так, чтобы длинная сторона была 2400 или 3000 px (мелкие фото **увеличиваются**, предел 8 Мп), бинаризуется порогом Оцу; длинные горизонтальные (≥ 1/15 ширины) и вертикальные (≥ 1/30 высоты) отрезки — линии таблицы — стираются. Чистая Java без Android API: тот же код проверяется на ПК (`tests/OcrPreprocessCheck.java`).
- Три прохода Tesseract на страницу: 2400 px «колонка» (PSM 4), 3000 px PSM 4, 2400 px «блок» (PSM 6). В документе больше 3 файлов — только первый проход, чтобы не ждать минутами. Мост возвращает `passes`, а `extractBest` выбирает строки из прохода, где суммы строк сходятся с «Итого» разделов, и голосует по полям между проходами.
- `NativeOcr.kt`: мост WebView к локальному движку. Нет HTTP-клиента, адреса сервера и сетевых запросов. Отдельный рабочий поток, прогресс, отмена через Tesseract stop.
- `web/document-parser.js`: локальные правила извлечения (с 0.15: заголовок «Дата выполнения работ», VIN и пробег в соседних ячейках под заголовком, «ООО/000/OOO», колонки «Кол-во / Цена / Сумма», «Итого» разделов как проверка, OCR-ошибки кавычек) даты выполнения, пробега, VIN, номера документа, сервиса, итога и строк работ/материалов. Неоднозначные поля остаются пустыми. Дата печати не становится датой ТО, рекомендации не становятся выполненными работами.
- `web/documents.js`: проверка, редактирование, оригиналы и сохранение в историю. Проверяется VIN, дата, числа, дубли идентичных файлов. Текущий пробег и весь регламент ТО автоматически не меняются.

Оригиналы и результаты — IndexedDB устройства; текстовая история — localStorage. Удаление аккаунта очищает обе базы. Исходный JSON-экспорт профиля не включает бинарные оригиналы (AUTO-35). Синхронизации/резервного копирования пока нет. Очистка данных приложения удалит локальную историю.

Серверный эксперимент 0.9 удалён из актуальной ветки; его исходники доступны в истории Git. Docker и Python-сервис пользователю не нужны.

## Сборка

```bash
python3 tools/build_prototype.py
gradle :app:assembleDebug
```

Задача `preBuild` запускает `tools/prepare_ocr_models.py`: **на компьютере сборки**, а не на телефоне. Она скачивает `rus` и `eng` из закреплённого коммита tessdata_fast `87416418657359cb625c412a48b6e1d6d41c29bd`, проверяет SHA-256 и упаковывает обе модели в APK. Уже скачанные проверенные файлы используются повторно. Повреждение/отсутствие модели завершает сборку ошибкой; скрытой загрузки при первом запуске нет.

Для первой сборки нужны Python 3, Java 17, Android SDK/Gradle и интернет для зависимостей. Для использования готового APK интернет не нужен. Лицензии и источники: [third-party-ocr.md](third-party-ocr.md).

## Проверки

- `node --test tests/document-parser.test.cjs`: русский разбор, рекомендации, неоднозначность, несуществующие даты, отсутствие сетевого транспорта в OCR.
- GitHub Actions: сборка APK, проверка наличия/хешей обеих моделей внутри APK.
- Android instrumentation на эмуляторе API 29 с авиарежимом, отключёнными Wi-Fi и мобильной сетью: первый запуск без извлечённых моделей, русское фото, растровый PDF на две страницы, отмена и повреждённый файл.

## Ограничения

- Колонки таблиц (количество, цена, сумма) распознаются для типовых нарядов; переносы названий на вторую строку и нестандартные таблицы по-прежнему требуют проверки; AUTO-32.
- EXIF и ручной поворот поддерживаются. Нет полноценного выпрямления перспективы/изгиба и оценки бликов; AUTO-33. Снимайте прямо сверху.
- Скорость зависит от телефона. Фото ограничены 25 Мп при входе, декодируются с уменьшением до примерно 4 Мп, затем для OCR приводятся к 2400/3000 px (до 8 Мп); PDF — постранично до 4 Мп. Три прохода занимают в 2–3 раза больше времени, чем один.
- Уверенность показывается по странице, не как калиброванная вероятность каждого поля; нет подсветки координат поверх оригинала.
- Повторное фото того же документа не обязательно определяется как дубликат; AUTO-34.
- Обычная веб-страница не содержит Android-движок: она честно предлагает использовать Android APK, без возврата к серверной обработке.
- Проверка на реальных обезличенных наряд-заказах и физических телефонах остаётся обязательной перед выпуском; эмулятор её не заменяет.

## Сборка 0.16 — тестовая (AUTO-42)

Подготовка снимка (`OcrPreprocess.java`): увеличение Lanczos-3 до 2400/3000 px, выравнивание фона (тени, градиент света), выпрямление наклона (−8…8°), стирание линий таблицы; проходы — серый 2400 px «колонка» и «блок» + ч/б 3000 px «колонка». Разбор (`document-parser.js`): голосование по каждой строке между проходами с приоритетом арифметики «кол-во × цена = сумма», количество из суммы/цены при нечитаемой колонке, VIN по структуре ISO 3779, пробег под строкой VIN, число колонок без заголовка — только если подтверждает арифметика.

Как проверялось:
- `tools/ocr_replay` — повтор конвейера APK на ПК: Tesseract 5.5.1 и Leptonica из исходников Tesseract4Android 4.9.0, модели из APK, тот же Java-класс подготовки, `document-parser.js` из APK. Скан наряда пользователя и 13 вариантов (масштаб 1.2–4.5×, JPEG q40/q60, наклон, перспектива, тень): все поля и строки верны. Вариант 0.8× (493×717 px, текст ~5 px) не проходит — данные в пикселях потеряны; нейросетевое повышение разрешения (FSRCNN, ESPCN, LapSRN, EDSR) не помогло и выдумывало цифры, поэтому не встроено.
- Эмулятор Android 10 в CI (`RealDocumentAcceptanceTest`): движок APK + `document-parser.js` из APK в WebView на 6 синтетических нарядах двух вёрсток — все верны; тексты проходов совпали с повтором на ПК в 16 из 18 проходов побайтно, в 2 — 1–2 слова.
- **Не проверено:** сам скан пользователя в приложении на телефоне. 0.15 на телефоне заполнила только номер, хотя её повтор на ПК распознал этот скан полностью; причина не найдена. Это AUTO-42.

## Проверка AUTO-41 (сборка 0.15)

Фото заказ-наряда-таблицы 616×896 px, на котором 0.10–0.14 находили только номер и дату. Тот же Tesseract 5 и модели `tessdata_fast`, та же Java-предобработка:

| Вариант | Поля из 6 | Строки работ/запчастей |
|---|---|---|
| Как в 0.14: исходное фото, PSM 6 | 2 | мусор |
| 2400 px, PSM 4 | 6 | 5 из 5 |
| 3000 px, PSM 4 | 5 (кавычка прочитана как «з») | 5 из 5 |
| Три прохода + голосование (0.15) | 6 | 5 из 5, рекомендация не попала в работы |

Обезличенный текст прохода — `tests/fixtures/order-table-ocr.txt`, сам снимок в репозиторий не входит. На физическом телефоне результат ещё нужно подтвердить (AUTO-36).
