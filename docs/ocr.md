# AUTO-31: импорт наряд-заказов без LLM

Ветка `feature/document-ocr`, сборка 0.9. Основная ветка не изменяется. Тестовый APK называется «АвтоХаб OCR», applicationId `ru.autohub.app.ocr`; устанавливается рядом с основным приложением, с отдельными данными.

## Что реализовано

История → «+» → «Сканировать наряд-заказ». Камера (полный снимок), JPG/PNG/WEBP и PDF, до 10 страниц / 16 МБ на запрос. Разбор на CPU через Tesseract `rus+eng`, Pillow и PDFium. Нет облачного OCR, LLM, платежей за страницы. Библиотеки: Tesseract — Apache-2.0; Pillow — HPND; pypdfium2 — Apache-2.0/BSD-3-Clause, PDFium и зависимости имеют свои notices; FastAPI — MIT; Uvicorn — BSD-3-Clause. Сохраняйте лицензии зависимостей при распространении.

Результат — редактируемый черновик. Извлекаются подписанные пробег, VIN, номер документа, дата закрытия/выполнения, название сервиса, итог к оплате. Конфликтующие значения остаются пустыми. Разделы работ/материалов разбираются консервативно, строки сохраняются как текст; количество/цена/сумма строки заполняются вручную. Рекомендации не импортируются как работы. Дата открытия/печати не подставляется в дату выполнения.

Пользователь видит текст OCR, источник каждого поля и изображения всех страниц (включая PDF). Перед сохранением требуется подтверждение выполненных работ. Проверяются VIN, дата, числовые поля, повторная загрузка идентичного файла и расхождения итогов. Пробег автомобиля и `lastTOkm`/`lastTOdate` не меняются автоматически.

Оригиналы и результат OCR сохраняются в IndexedDB на текущем устройстве; текстовая история — в существующем localStorage. Повторно открыть страницы: история → заказ-наряд → оригинал. Удаление аккаунта удаляет и документы. Существующая выгрузка JSON профиля не включает бинарные оригиналы: это ограничение записано в AUTO-35. Очистка данных приложения удаляет локальные документы; синхронизации и резервного копирования пока нет.

## Запуск своего OCR-сервера

На сервере с Docker, из корня репозитория:

```bash
export OCR_API_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
# Сохраните ключ в своём менеджере секретов. Не коммитьте его.
export OCR_ORIGINS="https://your-web-app.example"
docker compose -f compose.ocr.yml up -d --build
```

Сервис слушает только `127.0.0.1:8080`. Настройте HTTPS reverse proxy своего домена на этот адрес: лимит тела 24 МБ, таймаут обработки/чтения 780 секунд. Например, для nginx в нужном `location`:

```nginx
client_max_body_size 24m;
proxy_read_timeout 780s;
proxy_send_timeout 780s;
proxy_pass http://127.0.0.1:8080;
```

В шторке импорта раскройте «Подключение к своему OCR-серверу» и укажите базовый адрес `https://ocr.example` без `/v1/...` и ключ. Ключ держится только в памяти сессии, не сохраняется в localStorage и не попадает в экспорт. Android передаёт запрос через выделенный HTTPS-мост, без редиректов; веб-клиент — через fetch с CORS. CORS разрешает только явно указанные origins. Локальная веб-проверка допускает `http://localhost:8080`; Android требует HTTPS.

Обработка бесплатна в части ПО, но использует ресурсы вашего сервера. OCR-контейнер не хранит документы после запроса: временные файлы удаляются, access-log отключён. Ограничены размер, страницы, пиксели, таймаут каждого OCR-прохода. Одновременно обрабатывается один запрос; следующий получает 429. Это частный MVP с общим серверным ключом. Для массовой публикации нужна серверная авторизация пользователей и квоты (AUTO-22/AUTO-36).

Сейчас сервер **не развёрнут**: в репозитории есть код и Docker-конфигурация, адрес сервера не задан. GitHub Actions не является постоянным OCR-сервером.

## Проверка

```bash
python -m pip install -r server/requirements.txt pytest httpx
# Linux: установить tesseract-ocr, tesseract-ocr-rus, tesseract-ocr-eng, fonts-dejavu-core
python -m pytest server/tests -q
python3 tools/build_prototype.py
node --check web/documents.js
```

Тестовые документы создаются программно и не содержат данных клиентов. Они проверяют русский текст на изображении и растровом PDF, даты/пробег/итог, отсутствие рекомендаций в работах, неоднозначные поля, авторизацию и ограничения. Это не измерение точности на реальных документах сервисов. Перед выпуском требуется выборка реальных обезличенных снимков и проверка Android-камеры на устройстве.

## Ограничения

- Нет гарантированного восстановления таблиц незнакомой формы, объединения переносов и колонок (AUTO-32).
- EXIF и поворот по OSD учитываются; коррекция сильной перспективы/изгиба и полноценная оценка резкости — AUTO-33. Снимайте прямо сверху.
- Дедупликация по точным байтам файлов; повторное фото того же документа может не обнаружиться (AUTO-34).
- Геометрия OCR относится к обработанному изображению; интерфейс показывает текст источника и страницу, без наложения координат на оригинал.
- Старая демонстрационная история не удаляется автоматически, чтобы не затронуть пользовательские записи. Новые реальные машины больше не получают демо-записи.
- Штатный расчёт календарного ТО остаётся прежним (AUTO-37); импорт не выдаётся за прохождение всего ТО.
